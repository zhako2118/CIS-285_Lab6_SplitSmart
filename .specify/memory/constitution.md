# SplitSmart Constitution

## Core Principles

### I. Java 21
The project will use Java 21 as the primary programming language due to its modern features, long-term support, and compatibility with the project's requirements.

### II. Maven
Maven will be used for dependency management, build automation, and maintaining a standardized project structure.

### III. Java Swing
The graphical user interface (GUI) for the MVP (Minimum Viable Product) will be implemented using Java Swing. This implementation is for course purposes and does not replace the customer's requirement for web, Android, and iOS platforms.

### IV. JUnit 5
JUnit 5 will be used as the testing framework to ensure code reliability and correctness through unit testing.

### V. PlantUML
PlantUML will be used to create UML diagrams for visualizing system design and architecture.

### VI. Object-Oriented Design
The project will adhere to object-oriented design principles, including encapsulation, inheritance, and polymorphism, to ensure modularity and maintainability.

### VII. Separation of GUI and Business Logic
The GUI will be separated from the business logic to improve testability, maintainability, and scalability.

### VIII. BigDecimal for Monetary Calculations
BigDecimal will be used for all monetary calculations to ensure precision and avoid rounding errors.

### IX. Requirement Traceability
The project will maintain traceability between customer requirements (as outlined in `UserRequirement.md`) and implementation decisions to ensure all requirements are met.

### X. Mandatory Human Review of AI-Generated Output
All AI-generated code or documentation must be reviewed by a human to ensure accuracy, relevance, and compliance with project standards.

## Additional Constraints
- The Java Swing application represents an MVP for course implementation purposes. It is not intended to replace the customer's requirement for a web-based application with Android and iOS support.
- The project must comply with best practices for software engineering, including code reviews, testing gates, and adherence to the principles outlined above.

## Development Workflow
- All code changes must go through a peer review process to ensure compliance with the constitution.
- Testing gates must be enforced, including unit tests (JUnit 5) and integration tests where applicable.
- UML diagrams (PlantUML) must be updated to reflect changes in system design.

## Governance
- This constitution supersedes all other practices for the SplitSmart project.
- Amendments to this constitution require documentation, approval, and a migration plan.
- All pull requests and reviews must verify compliance with this constitution.
- Complexity in implementation must be justified and documented.
